# 市政 debug 松：議題分析模擬

> 本專案由一位個人參加者用 AI 協助製作，與主辦單位無關。`[AI模擬]` 的內容不是真實訪談，也不是真實市民的話；`[實證]` 的內容有可查證的出處；`【待補：…】` 需要真人提供。

## 這是什麼

一位市政 debug 松的報名者，在 AI 輔助模擬下，將個人在商業界常用的需求分析方法，套用到黑客松的議題，希望能幫助所有參與者一起產出品質更好的市政提案。

## 為什麼要做這個

黑客松的時間很短，參加者容易直接從題目裡的資料和舉例開始動手。這份模擬想補上一個步驟：在動手做之前，先看見利害關係人的多樣與衝突。這樣做出來的提案，比較容易說明「為什麼」，也比較能接住 100 天內落地的目標。

## 議題分析模擬採用的 7 個步驟

| 步驟 | 內容 |
|---|---|
| 1 | 列出利害關係人，分成**組織**（產業、政府、學術、非營利）與**個人**（居民、高齡者、身心障礙者、外籍居民等），並列出每一方可能的意見來源 |
| 2 | 用「身為…，我想要…，以便…」寫下使用者故事。題目原文的內容，放在它最可能代表的利害關係人之下 |
| 3 | 把「我想要…」當成一種可能的解法，追問「以便…」，找出真正的需求。過程中發現新的利害關係人，就加進清單 |
| 4 | 整理成使用者故事總表，每則故事有編號（例如 O03-US02、I01-US04） |
| 5 | 排出優先順序，並和利害關係人協商。不使用分數、權重或公式，因為輸入是質性資料。有衝突時，引入審議民主的方法 |
| 6 | 發想解法。每個解法列出它對應的故事，以及成效衡量方式（含現況數值與資料來源） |
| 7 | 評估每個解法需要的資料、API、資源、相關法規、隱私問題，以及負責局處 |

完整的方法說明（英文）：[human-inputs.md](human-inputs.md)。

各議題檔案共用的閱讀方式（標記、編號、排序原則等）：[如何閱讀議題分析](method.md)。

## 使用者故事總表的格式轉換

每個議題資料夾都有 `user-stories.csv`，如有需要，可以直接匯入 Google 試算表（檔案 → 匯入）。匯入後，試算表裡**看不到**本頁開頭的說明。請把下面這段文字放在**試算表標題或第一列**，讓讀者知道 `[AI模擬]` 的意思：

> 標記 [AI模擬] 的內容不是真實訪談，也不是真實市民的話；標記 [實證] 的內容有可查證的出處。

「優先順序」欄使用 MoSCoW（M、S、C、W）。試算表依字母排序時，順序會變成 C、M、S、W，所以建議用篩選，不要用排序。

修改任何 `issue-analysis.md` 或共用的 CSV 檔之後，請在 repo 根目錄執行這個指令（需要 Python 3）：

```
analysis/build_all.sh
```

這個指令會依序：更新 `stakeholders.csv` 的「議題」欄、為每個議題重建 `user-stories.csv` 並執行檢查、執行單元測試、產生 app 用的 JSON（預設寫到 `app/public/data`）。任何一步失敗就會停止。

檢查會確認編號（包含 `#2 O01-US01` 這種跨議題引用）、連結、標記、優先順序與 CSV 是否一致。指令更新了 CSV 時會提醒你，請一起提交。
