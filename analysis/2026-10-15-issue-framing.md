steps to build issues in the new structure:
1. list all possible stakeholders for each issue. the stakeholder list should consider but not limited to the following: people from industry/government/academic/non-profit, residents, elderly, people with disabilities, parents with strollers, night-shift workers, tourists, foreigners living in Taiwan... etc. the stakeholder definition should be as specific as possible. list possible input sources for each stackholder, e.g. "市長，你給我聽好了" messages, "[台北市陳情系統 1999](https://1999.gov.taipei)" for people who know how to use 1999 and who complain often, citizen-made report tools, foreign resident groups and community pages, 里長 and 里辦公處, a short survey, or watching the place in person... etc.
2. collect user stories for each stakeholder with "as a... (stakeholder), I want to... (what the stakeholder think the solution should be), so that I can... (what the stakeholder think they can benefit from the solution)" format, presented in a table. the suggestions in the original issue from the website should be included in the "I want to" of the user story of "主辦方／政策組（整理自市民意見）", depends on the information it provides
3. take the "I want to" part as a possible solution, and the "so that I can" part as the starting point of digging in real user needs. discuss and explore the "so that I can" part with the stakeholder. if new stakeholders pop up during the exploration, add them to the stakeholder list and collect user stories from them too
4. add the extended user stories gathered during the exploration to the table, and give every user story a number, grouped by stakeholder. e.g. S03-US02 (stakeholder 3, story 2)
5. prioritize the user stories and meanwhile negociate with stakeholders about the proiritization. when there are conflicts between different stakeholders, introduce deliberative democracy methods to grow consensus. the appropriate deliberative democracy methods may vary, depends on the nature of the issue. in real world city governmence, the team needs to consult professionals
6. brainstorm solutions that can fulfill as many prioritized user stories as possible. each solution should include the user stories it maps to and the methods for success measure. for each measure, add the current value (baseline) and the data source
7. calculate required data/api/resources, related laws, privacy issues, other possible concerns and the owner department for each solution to evaluate cost, feasibility and risks
