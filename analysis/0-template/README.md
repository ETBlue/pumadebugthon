# 議題分析範本

本資料夾是給其他參加者用的範本。用它可以把一個新的議題，分析成和本 repo 其他議題相同的格式。

| 檔案 | 內容 |
|---|---|
| [issue-analysis.md](issue-analysis.md) | 議題分析的完整結構：標題、開頭的說明、分析摘要、題目原文重點、步驟 1–7 與附錄。每個表格保留欄位名稱與一列範例 |
| [user-stories.csv](user-stories.csv) | 使用者故事表的欄位名稱與兩列假的範例 |
| README.md | 本說明 |

本資料夾不是一個議題。它不在 [issues.csv](../data/issues.csv) 中，所以檢查程式與網站都不會讀它。

## 怎麼用

1. 把整個資料夾複製成 `analysis/<n>-<名稱>/`，例如 `analysis/13-example/`。`<n>` 是議題編號，`<名稱>` 用小寫英文字母。複製後刪除新資料夾中的 `README.md`。
2. 在 [issues.csv](../data/issues.csv) 加一列：編號、資料夾、題目、來源（「主辦單位」或「參加者補充」）、新增日期（`YYYY-MM-DD`）。
3. 新的利害關係人加到 [stakeholders.csv](../data/stakeholders.csv)，取同一組（O 或 I）的下一個空號；已有的利害關係人沿用原編號。「議題」欄不要手改，由 `sync_stakeholders.py` 填。
4. 依步驟 1–7 填寫 `issue-analysis.md`。每個 `【填寫：…】` 都要換成內容。範例列（O00、I00 等假的編號）換成真的內容或刪除。範本中的 HTML 註解（`<!-- … -->`）是寫給你的說明，寫完後刪除。
5. `user-stories.csv` 不要手改。執行檢查時，`build_csv.py` 會從步驟 4 的表格重建它。
6. 寫完之後，用下面的指令確認還有沒有漏掉的地方。沒有任何輸出才算完成：

   ```
   grep -rn "【填寫" analysis/<n>-<名稱>/
   ```

`【填寫：…】` 和 `【待補：…】` 不同：

- `【填寫：…】` 是範本的空格，**全部都要刪掉**。
- `【待補：…】` 是完成的分析中「需要真人提供的資訊」，可以留下。寫法見[如何閱讀議題分析](../docs/method.md#標記)。

## 要遵守的規則

完整的規則在 [如何閱讀議題分析（method.md）](../docs/method.md)。最常用的是：

| 主題 | 規則 | 在 method.md 的哪裡 |
|---|---|---|
| 標記 | 每個表格格子以一個標記開頭：`[實證]`（有可查證的出處）、`[AI整理]`（AI 從真實資料整理，還沒有真人查核）、`[AI模擬]`（AI 推想，沒有資料）。只有步驟 7 的評估表與執行計畫表可以有多個標記 | [標記](../docs/method.md#標記) |
| 題目原文 | 題目原文是輸入來源，不是利害關係人。它的內容放在最可能代表的利害關係人之下，標記 `[實證]`。題目提到的解法構想放在步驟 6 | [題目原文](../docs/method.md#題目原文) |
| 編號 | 利害關係人：O 加兩位數字（組織）、I 加兩位數字（個人），各議題共用。故事：利害關係人編號-US 序號。W、N、C 與解法代號只在一個議題內使用，刪除後也不再使用 | [編號規則](../docs/method.md#編號規則) |
| 特別關注族群 | 步驟 1.3 有 6 列，順序固定。沒有納入的族群寫【待補：…】，只有真人可以決定它與本題無關 | [特別關注族群檢查](../docs/method.md#特別關注族群檢查) |
| 故事的格式 | 「我想要…」是他心中的解法，「以便…」是他自己得到的好處。放錯格子時改寫，並記在步驟 3 的改寫紀錄 | [步驟 2](../docs/method.md#步驟-2使用者故事的格式) |
| 排序 | 用 MoSCoW 排**需求**，不排故事或解法。不用分數、權重、名次或公式。件數不改變優先順序 | [步驟 5](../docs/method.md#步驟-5依需求排序) |
| 解法 | 以「我想要…」為起點，也參考其他城市或國家的做法，一定寫出國家名稱，不用極權國家的例子 | [步驟 6](../docs/method.md#步驟-6解法與需求對照) |
| 公開的政策與提案構想 | 也檢查公開的政策與提案構想。採用的想法用自己的話寫進解法，標記 `[AI模擬]`，不寫出來源的名稱，也不連結到來源。本 repo 把來源與解法的對照記錄在 [related-proposals/](../related-proposals/README.md) | [步驟 6](../docs/method.md#步驟-6解法與需求對照) |
| 衝突 | 衝突只在「我想要…」之間。先找以需求為本的解方；找不到時，再引入審議民主的方法 | [衝突](../docs/method.md#衝突與以需求為本的解方) |
| 評估 | 每個解法一節，有評估表與執行計畫表，項目與順序固定。也檢查相關的災害 | [步驟 7](../docs/method.md#步驟-7評估解法) |
| 空間類型 | 標題下方與 6.1 只寫 [space-types.csv](../data/space-types.csv) 的代碼，而且只用第 2 層（有「上層」）的代碼 | [空間類型](../docs/method.md#空間類型) |
| 領域與解法類型 | 空間類型的下一行寫「領域：」，用 [domain-types.csv](../data/domain-types.csv) 第 2 層的代碼 1 到 3 個。6.1 的「解法類型」寫 [solution-types.csv](../data/solution-types.csv) 的代碼 1 到 3 個。6.1 的「領域」通常留空，只有解法的領域和議題不同時才填。類型只是標籤，不是分數或排名 | [領域與解法類型](../docs/method.md#領域與解法類型) |
| 日期 | 6.1 的「新增日期」填當天，之後不再改。`updated-dates.csv` 由程式產生 | [新增日期與更新日期](../docs/method.md#新增日期與更新日期) |

其他規則：

- **中立**：不評價市府、政黨或任何人。不提選舉、候選人或政黨。談到境外的威脅時，不寫國家的名稱，用「境外敵對勢力」、「敵對國家」或「戰爭或武力威脅」。
- **「市長，你給我聽好了」資料**：資料已去識別化，不得嘗試反推陳情人身分，也不得使用真實個資，僅限於此黑客松活動使用。只寫件數與自己的話寫的摘要，不引用原始留言。有 10 則以上留言支持的格子才標 `[AI整理]`。不寫比行政區或主要道路更小的地點，也不寫店家、學校等的名稱。
- **資料的取得**：只做公開網頁的一般瀏覽與公開檔案的一般下載，不掃描或抓取市府或第三方的系統。
- **網站的資料**：分析會變成網站的資料檔。每個欄位的意思見[資料說明（data-guide.md）](../docs/data-guide.md)。產生的檔案不要手改。
- **跨議題分析**：新議題和其他議題有共用的利害關係人時，也要加進跨議題分析（見 [method.md 的跨議題分析](../docs/method.md#跨議題分析)）。

## 檢查

在 repo 根目錄執行（需要 Python 3）：

```
analysis/scripts/build_all.sh <輸出資料夾>
```

這個指令依序執行：更新 `stakeholders.csv` 的「議題」欄、重建 `user-stories.csv`、更新 `updated-dates.csv`、檢查每個議題（`check_analysis.py`）、檢查跨議題分析、執行單元測試、產生網站的 JSON 與資料表。任何一步失敗就會停止，並寫出哪裡有問題。各步驟的說明見 [analysis/README.md](../README.md)。

只檢查一個議題：

```
python3 -I analysis/scripts/check_analysis.py analysis/<n>-<名稱>/issue-analysis.md analysis/<n>-<名稱>/user-stories.csv
```

檢查通過，不代表 `【填寫：…】` 都已經刪掉。請另外用上面的 `grep` 確認。
