7 個市政痛點

以下是市政痛點，不是市政解答。題目來自「市長，你給我聽好了」蒐集的市民意見，由政策組整理。每隊選一題，也可跨題整合。每題附上可用的開放資料，作為起手參考。

「市長，你給我聽好了」資料（已去識別化）即將於此釋出。

// 可以用模擬的資料

作品重點是解法和可操作的介面，不必真的串接 API。資料不存在、沒開放或太難取得，就自己產生模擬資料，在 README 和 Demo 時說明哪些是真實資料、哪些是模擬的資料。不得使用任何真實個資。

#1把三千棵樹種回來

環境樹蔭公平 Shade EquityGIS

2025 年台北有 3,164 棵樹被移除。市府說明多為病蟲害或自然死亡，但東門市場附近一棵約 40 年、原本計畫移植保留的茄苳樹，卻遭到「誤砍」。台北一年移除三千棵樹，我們要如何找出城市空間把樹種回來，達到樹蔭公平？可參考新加坡「見縫插樹」。

開放資料點擊開啟資料集頁面
  • 臺北市行道樹及公園樹木分布圖data.gov.tw · CSV/JSON
  • 臺北市人行道固定設施物＿樹穴data.gov.tw
  • 臺北市人行道範圍圖data.taipei · JSON
  • 臺北市公園基本資料data.taipei · JSON
  • 臺北市行道樹路燈資訊網（含移樹履歷查詢）公園處
  • 逐年移除紀錄與原因未完整開放→ 可用模擬資料

#2找回消失的垃圾桶

市容IoT佈建最佳化

台北行人專用垃圾桶從全盛時期近 3,000 組，縮減到約 800 組。環保局依家戶垃圾違規棄置量評估裁撤或復設，但我們能不能結合行人流量、商圈分佈與民眾通報熱點，打造動態清理和智慧化的垃圾桶佈建建議？

沈伯洋說：垃圾桶很容易滿，可以設偵測系統。有些國家偵測到垃圾桶滿了才派人去收，不用一直定時巡邏；也有智慧垃圾桶，滿的時候裡面的機器會往下壓。 新聞

開放資料點擊開啟資料集頁面
  • 臺北市行人專用清潔箱（位置）data.gov.tw
  • 臺北捷運各站分時進出量（行人流量參考）data.taipei · CSV
  • 臺北市陳情系統類別資料data.taipei · CSV
  • 臺北市公車站牌位置圖data.taipei · SHP
  • 垃圾桶滿溢偵測資料不存在→ 可用模擬資料

#3鼠患四處跑，衛生安全怎麼辦

衛生GIS風險模型

傳統市場、夜市與餐飲聚落周邊的鼠患長年困擾市民，現行做法多停留在投藥與被動稽查。我們要如何整合餐飲登記密度、下水道管網分布、清潔隊清運排程與歷史通報，畫出「鼠患風險傳播地圖」，讓源頭治理精準到位？

沈伯洋說：老鼠要有食物和管道才能持續，錯過繁殖期就要等下一次才能處理。要做好垃圾與廚餘焚燒前的密封管理、確認垃圾車是否足夠、翻修管道與地下水道，並在繁殖期投放藥物，把前端預防做好。 新聞

開放資料點擊開啟資料集頁面
  • 臺北市陳情系統類別資料（含病媒通報）data.taipei · CSV
  • 臺北市污水下水道管線data.taipei · CSV
  • 臺北市雨水下水道人孔資料data.taipei · CSV
  • 臺北市食品業者登錄數（分區）data.taipei · CSV
  • 臺北市食材登錄平台：夜市專區衛生局
  • 見鼠地圖 Rat Radar：民眾通報（可匯出 CSV）民間
  • 逐筆餐飲業者位置、清運排程未完整開放→ 可用模擬資料

#4內湖尖峰車流好比停車場

交通即時資料儀表板

平日 07:00–09:30，數萬輛汽機車擠進成美橋、民權大橋與堤頂大道。如果把每 15 分鐘湧入內湖的車流熱點攤在陽光下，就能替企業算出「分批上班、彈性工時」對通勤與營運的好處。我們要如何整合高快速道路、聯外橋樑的 VD 流量與即時路況，做出「平日晨尖峰內科車流熱力儀表板」，作為市府與企業協商彈性工時的數據後盾？

開放資料點擊開啟資料集頁面
  • 臺北市車輛偵測器（VD）靜態資料data.taipei
  • 縣市即時路況（VD 每 5 分鐘統計）data.gov.tw · API
  • TDX 運輸資料流通服務平臺（需申請金鑰）交通部
  • 臺北捷運各站分時進出量（文湖線）data.taipei · CSV
  • 歷史 15 分鐘 VD 序列需自行累積→ 可用模擬資料

#5公車路網如何即時反應需求

交通最佳化勞動條件

台北公車路線長年疊床架屋，許多幹道路線與捷運高度重疊、互相競逐。我們要如何用站點上下車刷卡資料，算出各站真實的搭乘熱區與冷區，重劃捷運接駁與離峰低運量區塊，設計適合導入 DRTS 或小型巴士的動態路網？加分方向：把駕駛長過勞納入考量，例如盤點折返點的休息與大車暫停空間，把休息時間排進班表。

開放資料點擊開啟資料集頁面
  • 臺北市公車路線軌跡data.taipei · JSON
  • 臺北市公車站牌位置圖data.taipei · SHP
  • 臺北市預估到站時間（公車）data.taipei · JSON
  • 臺北市聯營公共汽車客運業務統計data.taipei · CSV
  • TDX 運輸資料流通服務平臺交通部
  • 各站上下車刷卡人次未開放→ 可用模擬資料

#6危老耐震如何查，風險評級怎麼找

居住安全加權模型都更

台北面臨「人老＋屋老」的雙老困境。50 年以上老屋在 2025 年突破 20%，2035 年將破 50%，2045 年超過 65%，代表多數房屋是在 921 地震修正耐震法規之前興建。我們要如何整合屋齡、建築結構、高齡人口、土壤液化潛勢與狹小巷弄消防搶救困難圖資，建立「危老耐震風險加權評級模型」，讓市府科學化排出老屋健檢與公辦都更的優先順序？

開放資料點擊開啟資料集頁面
  • 臺北市土壤液化潛勢圖data.taipei · GeoJSON
  • 臺北市各里人口數按年齡分data.taipei · CSV
  • 臺北市現有營造建築物棟數（含屋齡別）data.taipei · CSV
  • 臺北市消防通道清冊（搶救困難地區）data.taipei · CSV
  • 臺北市政府土壤液化潛勢查詢系統工務局
  • 逐棟屋齡、結構類型未開放→ 可用模擬資料

黑客松規則

報名即表示同意以下規則。違反行為準則者，主辦單位得請其離場並取消作品資格。

報名

  1. 報名已提前於 10/14（三）14:00 截止，名額 80 人。入選後將公布名單與 email 通知，沒入選則不另行通知。
  2. 可以單人組隊，每隊至少一名隊員，重複報名者將取消參與資格。
  3. Day 1 在 Discord 提案，不另外媒合隊友，志同道合的隊伍可自行整合。
  4. Day 2 現場依議題分桌或分區。同組至少一人到場，其他成員可遠端協作。
  5. 報名資料只用於本活動聯繫。

資料使用

  1. 可以用模擬的資料，不必真的串接 API。
  2. README 須註明哪些是真實開放資料、哪些是模擬資料，Demo 時口頭說明。
  3. 「市長，你給我聽好了」資料已去識別化，不得嘗試反推陳情人身分，也不得使用真實個資。「市長，你給我聽好了」資料僅限於此黑客松活動使用。
  4. 開放資料依各資料集授權使用，多數為政府資料開放授權條款。

作品規範

  1. 形式不限：App、網站、儀表板、系統原型、聊天機器人皆可，以可快速驗證的 MVP 為目標。
  2. Demo 時現場操作，只有簡報或設計稿不算。
  3. Day 1 起可開始討論與寫程式；可用開源套件與 AI 工具，須於 README 註明。
  4. 建議在 README 寫「如果市府上任 100 天內要落地，需要做什麼」：哪個局處、哪些資料、多少成本。
  5. 10/24 16:00 前透過主辦單位提供的隊伍專屬連結送出，填寫作品名稱與作品網址，可另附 GitHub 或 GitLab 程式碼網址；成員依報名資料。

Demo 與票選

  1. 不設評審、不排名次，以線上票選選出前三名。
  2. 現場 Demo 開放 10 組（視情況增至 15 組），10/24 16:30–17:00 直播，每組約 2 分鐘，現場填單抽順序。
  3. 票選 10/24 16:30 開放，10/31（六）18:00 截止，在本頁投票。
  4. 投票須以 Google 或 LINE 登入本站，每個帳號限投一次，最多選 3 件作品；灌票或自動化投票不予計入，同票並列。
  5. 前三名經團隊同意，於票選截止後 7 日內刊登於沈伯洋競選官網。無獎金。

著作權與開源

  • 著作權歸團隊所有。
  • 經團隊同意，作品以開源授權（建議 MIT 或 CC BY 4.0）收錄於ㄅ級分持續迭代；不同意不影響參加與票選。

行為準則

  • 互相尊重，不分背景、性別、年齡與政治立場，禁止騷擾、歧視與人身攻擊。
