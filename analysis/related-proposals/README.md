# 公開提案的來源對照

本資料夾記錄：其他公開的政策與提案中，哪些項目和本專案各議題的哪些解法有關。對照表是 [relations.csv](relations.csv)。

## 為什麼和議題分析分開

- 議題分析要保持中立。2026-10-28 各議題參考公開的政策與提案構想，用自己的話補充了一些解法，但議題分析、跨議題分析與網站都**不寫出來源的名稱，也不連結到來源**。
- 本資料夾只記錄「同樣的構想也出現在哪裡」，讓真人可以回頭查證。它不評價任何來源，也不代表本專案支持或反對任何來源。
- 本資料夾的內容不會出現在網站上。
- 各議題檔案開頭的說明寫著「來源對照見 `analysis/related-proposals/`」，指的就是這裡。

## relations.csv 的欄位

| 欄位 | 內容 |
|---|---|
| `source_id` | 來源項目的編號（P、H、C 加三位數字） |
| `source` | 政策、黑客松作品或程式連儂牆 |
| `title` | 來源項目的名稱。名稱中看起來是團隊或作者名稱的部分已經拿掉 |
| `link` | 來源項目的網址 |
| `issue` | 本專案的議題編號，例如 `#1` |
| `solution` | 相關的解法，例如「解法 S1、S2」。「不採用」的列留空 |
| `relation` | 相同、部分相同、新增或不採用（見下一節） |
| `note` | 本專案自己寫的說明：這個項目和解法的關係，以及議題分析有沒有改變 |

- 一個來源項目和幾個議題有關時，每個議題各一列。
- 表格依議題編號，再依 `source_id` 排列，不依件數或重要性排列。
- 同一件作品同時出現在黑客松作品與程式連儂牆時（C005 與 H020、C012 與 H010、C015 與 H008），兩列都保留，`note` 說明它們是同一個構想，只算一次。

## 關係的種類

| 關係 | 意思 |
|---|---|
| 相同 | 議題分析的解法已經有這個構想，議題分析沒有改變 |
| 部分相同 | 構想的一部分已經在解法中；其他部分不在本題範圍，或依本專案的規則不採用。議題分析沒有改變 |
| 新增 | 議題分析依這個構想，用自己的話補充了解法的內容（標記 `[AI模擬]`），或新增了解法。改了什麼寫在 `note` |
| 不採用 | 構想和本題的需求沒有直接的關係，或和本專案的規則不合（例如用投票或分數排序、替建物或地區評等）。`note` 寫出原因 |
