ETBlue's objective: I would like to patch hackathon issues with feature analysis skills I'm using in business world. to achieve that goal, I need to analyze all issues, so that other participants can build their proposal based on the analysis if they want to

steps to analyze the issues:
1. list all possible stakeholders for each issue. the stakeholder list should consider but not limited to the following: people from organizations (industry, government, academic, non-profit) and individuals (residents, elderly, people with disabilities, parents with strollers, night-shift workers, tourists, foreigners living in Taiwan... etc.). the stakeholder definition should be as specific as possible. list possible input sources for each stakeholder, e.g. "市長，你給我聽好了" messages, "[台北市陳情系統 1999](https://1999.gov.taipei)" for people who know how to use 1999 and who complain often, citizen-made report tools, foreign resident groups and community pages, 里長 and 里辦公處, a short survey, or watching the place in person... etc. "主辦方／政策組" should be excluded from stakeholders, as their inputs represent various stakeholders participated in the "市長，你給我聽好了" event
2. collect user stories for each stakeholder with "as a... (stakeholder), I want to... (what the stakeholder thinks the solution should be), so that I can... (what the stakeholder thinks they can benefit from the solution)" format, presented in a table. the content in the issue text becomes a story under the stakeholder it most likely speaks for. tag it [實證] with the source "題目原文". when an "I want to" belongs to multiple stakeholders, file user story under all stakeholders to make sure the solution-stakeholder mapping stays alive when people need to trace the decision making process in the future. each user story keeps the stakeholder's own "so that I can". add a group column (for example "相同訴求編號" W01, W02…) that links rows with the same "我想要"
3. take the "I want to" part as a possible solution, and the "so that I can" part as the starting point of digging in real user needs. discuss and explore the "so that I can" part with the stakeholder. if new stakeholders pop up during the exploration, add them to the stakeholder list and collect user stories from them too
4. add the extended user stories gathered during the exploration to the table, and give every user story a number, grouped by stakeholder. e.g. O03-US02 (organization stakeholder 3, user story 2) or I01-US04 (individual stakeholder 1, user story 4). a stakeholder found in step 3 gets the next free number in its own group
5. prioritize the user stories and meanwhile negotiate with stakeholders about the prioritization. when there are multiple stakeholders asking for the same "I want to", consider all of them for priority arrangement. do not use quantitative methods like scores, weights, ranks, or formulas when prioritizing qualitative inputs. when there are conflicts between different stakeholders, introduce deliberative democracy methods to grow consensus. the appropriate deliberative democracy methods may vary, depends on the nature of the issue. in real world city governance, the team needs to consult professionals
6. brainstorm solutions that can fulfill as many prioritized user stories as possible. each solution should include the user stories it maps to and the methods for success measure. for each measure, add the current value (baseline) and the data source. ideas from 沈伯洋 go straight into this step, with the source cited
7. calculate required data/api/resources, related laws, privacy issues, other possible concerns and the owner department for each solution to evaluate cost, feasibility and risks

what ETBlue expects the AI agent to do:
* simulate the steps above

* save the artifact in .md format, and put the files in the issue folder (e.g. `/analysis/1-trees`)
* when it comes to step 5, list suggested prioritization methods for different contexts
* write all artifacts in zh-TW
* take issue #2 as pilot and then expand all other 5 issues. use the #2 pilot as the format model for the other issues, including the CSV file
* place template files (.md and .csv) in issue #7 folder, and a README file in the analysis folder as a quick intro for other hackathon participants
