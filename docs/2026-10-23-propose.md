我是牙敗來不及組隊的 ET，我做的是自由題，叫「市政提案小幫手」，因為平常在業界開發新功能都要做需求分析，結果變成沒先看到 user story 就沒辦法下決定，所以報名以後要選主題，我就出現選擇障礙，只好先請 Claude Code 模擬政策制訂的前期研究，結果做下去發現比我想的複雜，就乾脆把這個當作我的黑客松主題

具體來說是把我平常做需求分析的流程改寫一下，變成議題分析的 SOP 請 AI 照著模擬，然後用網頁展示分析結果。產出的成果有三種，
* 一個是人類跟 AI 都可讀的 markdown 格式的分析報告，
* 一個是專門給機器讀的 csv 或 json 檔案，
* 一種是專門給人類讀的網頁介面。
使用者也有三種，
* 第一種是像我們這樣想參與政策制訂的公民，可以在提案前先看看這個議題有哪些利害關係人要考慮，
* 第二種是政府負責政策研究或民間企業做使用者研究的人，可以查詢市府以前做過的研究有沒有跟手上案子相關可以拿來參考的，
* 第三種是公民科技社群或民間企業的開發者，可以把結構化資料拿去應用在別的地方

因為 AI 模擬的內容需要人工查證跟確認，所以如果真的採用，還會需要一個管理後台，讓有權限的人可以校正 AI 模擬的內容，當一個議題的實證覆蓋率到達一定程度以後，這個分析結果才能算是有可信度

我有有把初步的分析結果貼在各主題的頻道，想說順便觀察一下是不是真的對提案有幫助，或者說需要怎麼調整，明天打算做網頁呈現的部分，還有看能不能把其他 puma 的政見也加進來一起分析。不過因為我是公共行政的麻瓜，希望有熟悉市政府研考作業的人可以給點意見

我想知道一般政策制訂的前期研究，是如何從利害關係人群體收集到他們各自的需求呢？
